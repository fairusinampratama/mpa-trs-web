# Part D — Admin information architecture and CRUD

## Minimal navigation and responsibility

**Review queue · Programmes & activities · Works & learning · Media permissions · Sources (restricted) · Corrections/history.** System configuration/accounts remain admin-only. No organiser account requirement. Cohorts/divisions are small controlled reference pickers, not prominent top-level modules unless editing frequency justifies that later.

Submitter sends a simple brief/document through the existing agreed institutional channel. Central editor creates/deduplicates the record and public summary. Custodian attaches private evidence/version and controls originals. Reviewer checks facts, scope and source conflicts. Authorized publisher approves the exact public revision and permitted media uses. One appointed person may cover several roles; permissions remain distinct. No new committees or mandatory signatures assumed. Named primary/backup appointments remain operational owner decisions.

## One editing workspace

Header: title, stable ID, event state, editorial revision, public status. Tabs: **Ringkasan · Rangkaian/Pelaksanaan · Hasil & Karya · Media · Sumber & Tinjauan · Pratinjau**. Simple-event mode exposes only a short form with optional “Tambah rincian”; no six obligatory empty tabs. PDcycle adds **Pelaksanaan divisi**; child header shows “Konteks dari PDXXIX” rather than copied text.

Common controls: Simpan draf / Pratinjau publik / Ajukan tinjauan. Publish is separate, capability-gated and displays exact revision, uncertainty notices, unavailable works, withheld media and affected pages. Required errors are inline and focus-linked; progress is saved without pretending publication succeeded.

### A — Create BATAFIA XXXI (synthetic scenario)

1. Find BATAFIA programme; search duplicates; create occurrence labelXXXI, title, purpose/summary and optional cohort reference. Cohort label is not generated membership data.
2. Add forum phase and field phase. Add only known sessions to forum: title/topic, optional planned dates/place; no assumed syllabus. Reorder with Move up/down buttons.
3. Save pre-event draft; optional planned public preview only after explicit approval. No recruitment announcement generated automatically.
4. After execution, record actual per-phase dates/places/status. A canceled/incomplete session keeps its own state; field completion does not mark every forum session completed. Add source-backed application/results separately from aims.
5. Link works and choose media with exact proposed context. HOLD photos show privately with reason and are absent from public preview.
6. Submit; editor resolves conflicts or returns requested changes; publisher approves exact public revision. Missing forum results may still permit an honest field record; missing rights excludes the image rather than blocking all text.

### B — Create Tursina Explore13 (synthetic)

One TE occurrence, not a new hardcoded page. Enter objectives, planned destination/date, public-safe preparation summary; create/reorder journey legs with local IDs, actual places/dates and summaries. Later add reported observations and independent work relationships. Draft documentary intention remains an objective, not an available video. Conflicting return dates are separate assertions with one reviewed display choice. Published manuscript/download requires independent permission, not just activity approval.

### C — Create PDXXX (synthetic)

Create PD cycle, cohort association, common educational purpose and applicable preparation context once. Show five reference fields as **Belum ditambahkan** prompts, not invented completed child events. Add GH/RC/ORAD/LH/Caving execution records only as evidence/plans justify them. Each child has own date/place, divisions, learning standard, simulations, application/results and reporting state. Display inherited context as read-only linked values; allow an explicit sourced exception. One child may publish before another; cycle overview displays only approved child summaries, with incomplete coverage honestly stated. Fixing common context proposes a reviewed update to all dependent public views.

### D — Simple one-day independent event (synthetic)

Select Kegiatan mandiri. Enter working/public title, short purpose/account, known date/place and source. Programme, edition, cohort, sessions, outcomes, media and works remain collapsed/optional. Save→preview→review→publish. Minimum public archival record may have unknown date/place; the editor records that uncertainty. No long technical report, achievement or gallery required.

### E — Historical import (real structural example: PDXXVI / sparse TE12)

Search before create. Record title and identity evidence; preserve unknown date precision; attach multiple source assertions when contradictory. Keep planned/actual dates in different fields. Select a short approved summary and unresolved-note wording. No inferred years from Roman numerals. A private source attachment is not a download. Preview sparse mode; submit with gap notes. Publisher can approve metadata only; later enrichment creates a reviewed revision of the same record.

## Editorial lifecycle proposal

Draft → Submitted → In review → Approved revision → Published snapshot.

Changes requested returns a working draft with review notes. Approval is a checkpoint, not a permanent record property. Publishing can occur immediately after approval by the authorized publisher; no compulsory separate approver account if one designated person legitimately covers both responsibilities. Meaningful changes invalidate approval for the changed revision. Live snapshot remains until replacement is approved; withdrawn content disappears from discovery but keeps appropriately restricted audit history. Event execution, report acceptance, original availability and media rights are separate states.

Corrections: compare before/after public projection, source version and impacted records; record reason/editor/time. Missing evidence: return to draft or approve a deliberately limited projection, never approve an unsupported outcome. Duplicate: propose canonical survivor and alias/relation/media-use impact, review before merge; no automatic duplicate deletion. A source correction flags dependent claims for review; private source text never becomes public merely by propagation. A media-use withdrawal takes effect promptly without waiting to republish an unrelated article; restore only through approval. Content “delete” defaults to archival/withdrawal when referenced; permanent disposal follows later custody policy.
